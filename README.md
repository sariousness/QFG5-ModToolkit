# QFG5Extractor

QFG5Extractor is a suite of reverse-engineered C# extraction tools for parsing, extracting, and modifying bulk assets from the classic Sierra game *Quest for Glory V: Dragon Fire*. This toolkit enables automated, batch capabilities for `.SPK` game archives, `.MDL` (Hakenberg & BMPs) meshes, and panorama backgrounds directly through a unified, cross-platform Windows Forms UI.

## Features
- **Centralized Folder Setup:** Configure the game `DATA` folder and a separate Mods folder once in Settings. The app checks common original and GOG install locations on startup and defaults Mods to `Documents/QFG5 Mods`.
- **Organized Extraction:** Asset tools derive their source folders from the game data structure and place outputs under matching folders in the Mods directory, such as `cdn/GRA`, `cdn/QGM`, and `hdnw/mdl`.
- **SPK Tab:** Supports parsing nested archive structures within `.SPK` files, extracting or repacking multiple selected archives, and choosing uppercase output filenames when repacking.
- **Model Tab:** Transpiles native QFG5 `.mdl` models dynamically into open `.hak` files.
- **MDL Model Files:** Switch between list and thumbnail views for exported BMP textures; HAK outputs remain available in list view.
- **MDL Viewer (OpenTK):** A hardware-accelerated 3D viewer supporting skeletal animation assembly, multi-texture rendering, and external texture overrides.
- **Texture Editor:** Provides a vertical icon toolbox with an active-color swatch, an expanded canvas workspace, Space+drag panning, lasso and rectangular selections, sticker props, and a compact four-row palette of 256 representative RGB555 high-color samples that stays consistent across models. Zoom, brush size, and image adjustments are grouped in the context bar. Also includes bounded undo history, reset-to-original texture, and palette-preserving MDL injection. MDL Model BMP exports use the same display-palette range as the 3D viewer. The GRA tab can open a preview frame in the editor for image edits and inject it back into its source GRA.
- **GRA Tab:** Scans both `cdn/GRA` and `hdn/gra`, shows each resource's source folder, and keeps same-named resources from the two folders distinct. Switch between the detailed list and a thumbnail browser; thumbnails load incrementally to keep the UI responsive, and thumbnail selection supports Shift/Ctrl multi-select. The toolbar CM toggle applies column-major decoding to the selected resource(s). The reviewed CM selections are bundled as the built-in default; click **Save CM List** to create a per-user override at `%LOCALAPPDATA%/QFG5Extractor/gra-column-major.txt`. **Auto CM** applies the verified/bundled list to the selected resources, or all visible resources if none are selected. Mark favorites and restore a GRA from its `.qfg5extractor.bak` file. Extracted images and videos are written under the matching folder in Mods, and the completion dialog shows the full output folder path.
- **Message & Panorama Tabs:** Extracts QGM messages to editable text while keeping the original binary records and per-message metadata in `.qgmmeta` sidecars. **Repack All** rebuilds edited QGM files and then repacks `CDN.SPK` into `Mods/repacked`. Untouched records remain byte-identical; edited records are written as plain 8-bit text with the QGM obfuscation flag cleared. Pano Editor converts `.nod` backgrounds to editable BMPs; Rooms / Studio lists extracted views, labels known room IDs, and renders a cylindrical panorama preview using IMG angle metadata when available.

## Building and Running

### Prerequisites
- .NET Framework 4.5+ (Windows)
- Mono Runtime (Linux / Mac OS)

### Compiling on Linux/Mac
Ensure `mono-devel` or your distro's equivalent is installed with the MSBuild engine:
```bash
sudo apt install mono-complete
cd src
msbuild QFG5Extractor.csproj  # or use `xbuild` on deprecated Mono versions
mono bin/Debug/QFG5Extractor.exe
```

### Logs
The application provides real-time transaction debugging across all batches. If a parsing operation encounters anomalies, the suite gracefully ignores the corrupted mesh nodes without crashing and explicitly details the warning logs in `<Working_Directory>/qfg5extractor.log`, which can be cross-referenced natively inside the GUI by clicking **View Log**.

### Folder setup
Set the game’s `DATA` directory itself in **Settings**. It may contain the game’s `.SPK` archives directly or already-extracted `cdn`/`hdnw` folders. SPK archives are scanned directly in `DATA`; archives such as `CDN.SPK` and `HDNW.SPK` extract into the matching `Mods/cdn` and `Mods/hdnw` folders, preserving paths stored inside each archive. Opening the MDL, Panorama, or Message tab automatically extracts missing source files, creates missing previews or text outputs, and loads the available results into the list without overwriting existing files in Mods. Repacked archives are written to `Mods/repacked`; in the SPK tab, enable **Uppercase filename** to write repacked archive names in uppercase. Asset tools use extracted Mods folders when the corresponding source files are not present in `DATA`.

To edit messages, edit and save the `.txt` files under `Mods/cdn/QGM`, then click **Repack All** in the Message tab. Keep the blank-line paragraph structure of each message unchanged so the sidecar can retain exact message boundaries. The app rejects ambiguous boundaries, unsupported text characters, and unsupported QGM versions rather than writing a possibly invalid archive. A successful repack writes `Mods/repacked/CDN.SPK`; install that archive in the game’s `DATA` folder.

Panorama injection writes the edited palette and compressed pixels to `Mods/cdn/NOD` and `Mods/cdn/IMG`. Use **Edit Selected** in Pano Editor to edit a converted BMP in Texture Editor, then click **Inject to Pano**. Repack `CDN.SPK` in the SPK tab, then install the generated archive from `Mods/repacked` in the game’s `DATA` folder for the game to load the changes. Rooms / Studio uses the [QFG5 room ID list](https://www.qfgmods.net/wiki/QFG5_Rooms.html) to label known room and view IDs. The preview maps the room image onto a perspective camera view of a cylinder and reads the panorama start/end angles from its matching IMG header; when that metadata is unavailable, it assumes a full 360-degree panorama. Drag to pan and scroll to zoom. The camera fits its field of view to the extracted image and constrains panning to the available image range to avoid exposing black edges. Room-specific ROM distance limits, underwater distortion, and room sprites are not applied, so this remains an approximate preview rather than the game's complete renderer. The [room image format notes](https://web.archive.org/web/20251028234600/https://codecs.multimedia.cx/2023/11/qfg5-room-image-formats/) describe NOD palettes, IMG pixel layout, and related formats; see also the [QFG5 engine code and room-view notes](https://web.archive.org/web/20251109011305/https://codecs.multimedia.cx/2024/01/qfg5-now-with-some-code/) and [cylindrical projection article](https://web.archive.org/web/20251109015607/https://codecs.multimedia.cx/2024/02/qfg5-panorama-projection/). Use **Load BMP** to preview an external image.

To edit a GRA graphic, select its resource in the GRA tab, click **Edit Graphic**, make changes in Texture Editor, and click **Inject to GRA**. **Inject to MDL** remains visible as a separate action. The editor patches only the selected frame in place, preserves all file offsets and other frames, and keeps a one-time `.qfg5extractor.bak` beside the GRA. The **Restore** action keeps this backup and restores the original file. The image must keep its original frame dimensions and its encoded data must fit in the frame's existing space; otherwise injection stops without changing the file. Mode 1 preserves its depth bytes, and indexed colors are mapped to the original GRA palette. If the GRA is under Mods, repack the archive matching its source folder (`CDN.SPK` for `cdn/GRA`, or the appropriate HDN archive for `hdn/gra`) and install it in the game’s `DATA` folder.

The 3D Viewer can record its live viewport, including animation playback, to MP4. This requires FFmpeg available on `PATH` or an `ffmpeg` executable alongside the application. Keep the viewport size unchanged while recording.

Texture injection validates the edited MDL before replacing the selected file and saves a one-time `.qfg5extractor.bak` backup beside it. Use the circular-arrow action beside a model's favorite star to restore its original MDL and embedded texture from that backup; the backup is retained. Reset Original in the Texture Editor restores the extracted texture snapshot (using the pre-injection backup when available) on the editor canvas only; inject the texture to update the MDL on disk.

In the Texture Editor, hold Space and drag over the canvas to pan while zoomed in; middle-mouse drag is also supported. Lasso and rectangular selections can be used with the Hue/Saturation adjustment. The model-independent palette displays 256 representative colors from the game's RGB555 high-color range in a compact, scrollable four-row grid.

The Save Editor validates the documented QFG5 save header, noise length, inventory count, and inventory block location before loading. Before the first overwrite it creates `save-file.QG5.bak` without replacing an existing backup. Saving refuses to overwrite a file changed externally since it was loaded and verifies that the written file length matches the loaded file. Use the **Inventory**, **Character**, and **Flags** buttons to switch screens. Inventory retains the list/icon views, searchable categorized item catalog, drag-to-replace, and right-click duplicate/insert/delete actions. Item names come from the bundled `objects.dat` catalog, resolved relative to the application or project resources rather than the process working directory. Inventory thumbnails decode saved item IDs directly into `101xxx` sprite IDs; `icon_mapping.dat` entries remain optional overrides, shared scroll/drink fallbacks are restricted to the matching category, and Tinderbox is rotated clockwise for display. On the **Character** screen, select a model by name or numeric ID (0-255) to see its larger spinning preview update immediately, and choose a room from the supported location catalog. Character details appear at the upper left, the landscape room preview at the lower left, and the model preview alongside them. Drag either splitter to resize the detail, room, and model preview areas; the room preview receives a taller initial share. The model and room controls wrap and resize their dropdowns when the window is narrow. The model preview loads the matching three-digit `.MDL` file (for example, `010.MDL` for model ID 10) and a matching `.ANM` skeleton animation from the configured `hdnw/mdl` and `hdnw/anm` game or Mods folders, applying the first animation frame's bone matrices to the submeshes as a static pose while the model spins. It does not play the animation. If no compatible animation exists, the preview reports the problem instead of showing unassembled submeshes. The selected room preview loads its extracted panorama from `Mods/cdn/NOD`, using matching IMG angle metadata when available; drag to pan and scroll to zoom, with the camera fitted to and constrained by the extracted view. Click **Apply Model** or **Apply Room**, then the shared **Save** button. The **Flags** screen shares the loaded save and Save button; it locates the packed flag bytes by parsing the variable-length inventory, dialogue, and 133-room object-state sections before the 1,536-byte engine-state block. When that structural parse succeeds, flags use a little-endian, low-bit-first mask (eight sequential flags per byte); otherwise values display as **Unknown** and flag editing is disabled rather than guessing at an offset. A first in-game check confirmed that an edited flag appears in the game's deeds screen; broader testing across flags and saves is still pending. Keep the automatic `.bak` backup and verify any further edits in game. Model lookup uses a validated offset relative to the unique UTF-16 `Quest ` room label, with a validated record-marker fallback. If the save ends with only a partial `Qu` room-label prefix at the expected character-record offset, the editor displays the recovered character values read-only and disables character edits and saving; restore a complete backup or create a fresh in-game save. Character X/Y/Z, rotation, and size are shown read-only as interpreted values with their raw values for comparison. A matching file length does not guarantee that the game can load an edited save without crashing. Some models may lack animations, and not all rooms have been verified for safe loading; keep the automatic `.bak` backup before testing changes.
